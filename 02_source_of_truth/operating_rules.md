# Operating Rules

## Regla 1 — Leer antes de actuar

Todo agente debe leer `CURRENT_STATE.md` antes de proponer cambios.

## Regla 2 — Markdown primero

Sprint 1 debe mantenerse simple: Markdown, Git y estructura clara.

## Regla 3 — Decisiones versionadas

Las decisiones importantes se registran en `03_decisions/`.

## Regla 4 — Sesiones como historial

Las sesiones documentan contexto, pero no reemplazan decisiones aprobadas.

## Regla 5 — Handoffs claros

Todo handoff debe indicar estado actual, objetivo, restricciones, archivos relevantes y criterio de éxito.

## Regla 6 — No sobreingeniería temprana

No agregar backend, dashboard, embeddings, APIs ni automatizaciones hasta que estén planificadas en sprints posteriores.

## Regla 7 — Cada sprint deja algo andando

Ningún sprint debe ser meramente preparatorio. Cada sprint debe entregar valor operativo demostrable.
